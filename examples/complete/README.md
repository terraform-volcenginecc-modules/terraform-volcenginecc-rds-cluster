# Complete cross-AZ deployment

Create a DoubleNode RDS MySQL primary/standby across AZs with a ReadOnly replica, private writer/read-splitting and reader proxies, a parameter template, restricted database access, tags and fourteen-day running-instance backup retention.

This uses DoubleNode because the APIs restrict independent ReadOnly nodes and custom endpoint creation to that architecture. MultiNode uses readable Secondary replicas and service-created endpoints. The example requests two proxy CPU cores at instance creation. Writer creates before reader and destroys after reader. Addresses are generated by the service. Custom prefixes, public-download control and release-retention settings are not provided because the online Handler/Provider does not reliably support them.

Use Terraform 1.5.7 or OpenTofu 1.11.8 and Provider 0.0.73. Source `terraform-volcenginecc-modules/rds-cluster/volcenginecc` is the intended Registry address; publication/consumption is unverified.

Prepare `deployment.tfvars` with region, node_spec and network (vpc_id, subnet_id, security_group_ids, primary_zone_id, secondary_zone_id, reader_zone_id). Primary/secondary AZs must differ; reader can share either or use a third. Subnet must be in the primary AZ. Optionally set project_name and allowed_cidrs. Supply Provider credentials via VOLCENGINE_ACCESS_KEY/VOLCENGINE_SECRET_KEY and the password via TF_VAR_administrator_password.

```sh
terraform init
terraform plan -var-file=deployment.tfvars
terraform apply -var-file=deployment.tfvars
terraform plan -var-file=deployment.tfvars -detailed-exitcode
terraform output -json
```

The writer proxy writes to Primary and splits reads to replicas. The reader selects replicas without Primary fallback; lagged replicas can cause read failures. On 2026-11-05, Terraform 1.5.7 with Registry Provider 0.0.73 passed apply, independent checks of cross-AZ topology, proxy members, actual endpoint outputs, running parameters and fourteen-day running-instance backups, and a refreshed plan with no changes. SQL routing remains blocked by private-network reachability; replication behavior and failover require further verification. Use `tofu` in isolated State for OpenTofu.

For authorized cleanup, disable deletion protection in a separate apply, then destroy. Release retention is controlled by the service; Last/7 was observed, but is not a module guarantee. Retained backups can incur charges. Query deleted managed resources and retained backups; the caller's network remains external.

```sh
terraform apply -var-file=deployment.tfvars -var=deletion_protection=false
terraform destroy -var-file=deployment.tfvars -var=deletion_protection=false
```

Topology, password, storage, engine, network or parameter binding changes can replace the instance. Template edits do not guarantee live parameter propagation. The first standard destroy in the revised cycle passed, deleting five managed resources without retry or compensation. State was empty; independent API queries confirmed instance, managed proxies, allowlist and template absence. This remains a draft with SQL routing blocked and failover unverified.
